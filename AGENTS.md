# Phinary Arc

> Built with Arc Studio - money-powered apps in minutes

Project memory for future agents.

## What This App Does

Binary prediction markets (UP/DOWN vs a strike at a deadline) for BTC, ETH, SOL on Arc Testnet. Odds are Black-Scholes (r = 0, realized vol from the oracle) plus a house edge. A shared USDC vault backs payouts and earns the edge. No tokens: positions and vault shares are internal accounting. Users can sell back before expiry and set stop-loss / take-profit on the underlying price; the keeper (or anyone) executes them.

## Tech Stack

- Frontend: React 18, Vite, TypeScript, Tailwind, framer-motion, Recharts via shadcn chart (`src/components/ui/chart.tsx`)
- Web3: wagmi v2, viem, ConnectKit
- Contracts: Solidity 0.8.28 + Foundry in `contracts/`, tests in `contracts/test/` (186 passing)
- Chain: Arc Testnet (5042002), USDC `0x3600...0000` (6 decimals, ERC-20 view only)
- Fonts: Akt (primary), Manrope (numbers). Palette: #1083FF main, #97CB3D success/UP, #F44708 fail/DOWN, white text, opaque navy surfaces (canvas, card, raised, hover; each nesting level one step lighter, no borders).
- Design rules (enforced in `tailwind.config.js`): five font sizes only (12, 14, 16, 24, 40); radii card 24 > inner 16 > control 12 > badge 8; sentence case; one secondary text tone (`text-dim`); selected = filled (blue by default, green/red for Up/Down). Explanations go in `HelpTip` tooltips, never captions.

## Architecture notes

- No polling. `src/lib/realtime.ts` holds one viem WebSocket client; `src/hooks/useRealtimeSync.ts` subscribes to contract events, feed price updates and USDC transfers and writes into the react-query cache. Query hooks live in `src/hooks/data.ts` and keep previous data while refreshing (no loading flicker).
- Odds are computed in the browser with `src/lib/pricing.ts`, a port of the contract formula (`bun run scripts/quote-parity.ts` checks parity). The contract is only called to bet. A custom strike opens a market in the same flow as the bet.
- Markets are selected by duration (5m, 15m, 1h), not id, so the view moves to the next market without a reload.
- Positions live under the chart on the Trade page and show only active bets after a reload; History scans events from `VITE_DEPLOY_BLOCK`.
- Logo: `src/logo.svg` is the original upload (1254x1254 canvas). `src/assets/logo-mark.svg` is the same white artwork with the viewBox cropped to the glyph; the header uses that one.

- `contracts/lib/BlackScholesLib.sol`: ln/exp/sqrt/normal CDF and the binary price

- `src/components/PriceChart.tsx`: Coinbase line + strike + oracle marker + deadline + SL/TP lines + bettor avatars
- `scripts/keeper.ts`: price push, oracle poke, market rotation, settlement, order execution
- `scripts/setup.ts`: one-time feed registration and vault seeding

## Design decisions

- Withdrawals are priced at a conservative NAV (worst-case reserve on open markets), deposits at the plain balance, so LP timing cannot profit. Reserve per market = max(up,down) + ceil(0.99 * min) so sell-backs always stay possible.
- Trading uses oracle prices no older than `maxTradeStaleness` (120s). Oracle-update front-running is a documented residual risk of oracle-priced markets.
- Settlement requires the first oracle round at or after expiry; a feed phase-boundary round is rejected (market then voids after 24h with cost refunds).
- Avatars are address-based Gravatar identicons (no email).
- Keeper pushes mock feed prices from Coinbase on a 45s heartbeat or 5 bps move. Run `bun run keeper` to keep markets rolling.

## Share links

- Starter apps already ship `getShareBase`, `buildShareLink` and `installShareSync` in `src/lib/share.ts`; import them instead of rewriting them.
- Keep shareable state in the URL path or query, not in the `#fragment`.
- Never put a secret in the URL path or query. A bearer claim secret goes only in the `#fragment`.
